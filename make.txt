# Project: AI-Based Fruit Quality Inspection and Automated Sorting System

Act as a senior AI/ML engineer, computer vision specialist, and full-stack developer. Build a complete Industry 4.0 project named **FruitVision AI — Intelligent Fruit Quality Inspection and Sorting System**.

The system should use Convolutional Neural Networks (CNN) and transfer learning to automatically classify fruits based on their quality and detect damaged or rotten fruits.

The project must be suitable for a B.Tech CSE group project and should prioritize model accuracy, fast training, practical demonstration, and a professional user interface.

## 1. Project Objective

Develop an AI-powered fruit inspection system that automatically examines fruit images and classifies them into:

- Good: Fresh and acceptable fruits.
- Damaged: Fruits with visible physical damage, bruises, cuts, or defects.
- Rotten: Fruits showing signs of decay, mold, or spoilage.

The system should simulate an automated fruit quality inspection unit used in food processing and manufacturing industries.

## 2. Machine Learning Requirements

**CNN Architecture:** EfficientNetB0.

**Framework:** TensorFlow / Keras.

**Training platform:** Google Colab with GPU acceleration.

**Training limit:** Maximum 60 minutes.

**Preferred training time:** 15–40 minutes.

Use transfer learning with pretrained ImageNet weights. Do not train the CNN from scratch.

### Dataset Requirements

Use publicly available datasets:

1. Fruits-360 Dataset:
   https://www.kaggle.com/datasets/moltean/fruits

2. Fruit quality and defect image datasets:
   Search for publicly available datasets containing fresh, damaged, bruised, and rotten fruit images.

Use Fruits-360 for fruit recognition and suitable quality/defect datasets for quality classification.

Important:
- Do not assume Fruits-360 alone provides good, damaged, and rotten labels.
- Verify the dataset labels before training.
- Create a unified dataset with three classes: Good, Damaged, Rotten.
- Use only images that genuinely represent the corresponding quality category.
- Remove duplicates and corrupted images.
- Split data into training, validation, and testing sets.
- Avoid data leakage between splits.
- Use stratified splitting where appropriate.

If sufficient defect images are unavailable, clearly document the limitation rather than generating fake samples or misleading labels.

## 3. Model Training Pipeline

Implement the following pipeline:

1. Dataset downloading and extraction.
2. Image preprocessing.
3. Dataset visualization.
4. Class distribution analysis.
5. Train/validation/test splitting.
6. Image resizing to 224 × 224.
7. Data augmentation.
8. EfficientNetB0 pretrained model loading.
9. Transfer learning.
10. Fine-tuning selected layers.
11. Model evaluation.
12. Saving the best model.

### Initial training configuration

- Architecture: EfficientNetB0.
- Pretrained weights: ImageNet.
- Input size: 224 × 224 × 3.
- Batch size: 32, adjusted to available GPU memory.
- Optimizer: Adam.
- Initial learning rate: 0.001 for the classification head.
- Fine-tuning learning rate: 0.0001.
- Epochs: 10–20 maximum.
- Early stopping: Patience of 3.
- Loss: Categorical Crossentropy.
- GPU acceleration enabled.

Freeze the pretrained backbone initially and train the classification head. Then optionally unfreeze the final layers for fine-tuning.

Use EarlyStopping and ModelCheckpoint to save the best-performing model.

## 4. Evaluation Requirements

Target a test accuracy of 90% or higher where the dataset supports it.

Evaluate the model using:

- Accuracy.
- Precision.
- Recall.
- F1-score.
- Confusion matrix.
- Per-class classification report.
- Training and validation accuracy graphs.
- Training and validation loss graphs.

Evaluate on a separate held-out test set.

Test the model on previously unseen fruit images.

Display the predicted class and confidence score.

Do not hardcode accuracy values or fabricate evaluation results.

Pay special attention to class imbalance and false classification of rotten fruits as good.

## 5. Fruit Inspection Features

The application must support:

### Image Upload
- Upload JPG, JPEG, and PNG images.
- Predict fruit quality.
- Display the predicted class.
- Show prediction confidence.
- Display the original image.
- Display classification results.
- Provide recommendations based on the predicted quality.

### Multiple Fruit Detection
Allow users to upload an image containing multiple fruits.

Where feasible, implement fruit detection or individual fruit cropping before classification.

Classify each fruit separately and display:
- Total fruit count.
- Good fruit count.
- Damaged fruit count.
- Rotten fruit count.
- Overall quality percentage.

Do not assume that a single-fruit classifier automatically supports multiple fruits in one image.

## 6. Automated Sorting Simulation

Create an interactive conveyor belt simulation representing an industrial fruit sorting system.

The simulation should:

1. Display fruits moving along a conveyor belt.
2. Process each fruit using the trained CNN model.
3. Classify each fruit into Good, Damaged, or Rotten.
4. Route good fruits into the accepted-products section.
5. Route damaged fruits into the secondary inspection section.
6. Route rotten fruits into the rejected-products section.

Use animated sorting gates or simulated robotic arms.

Allow users to start, pause, and reset the simulation.

Display real-time counters for each category.

The simulation must use actual model predictions for uploaded test images or a defined set of test samples, not random classifications.
